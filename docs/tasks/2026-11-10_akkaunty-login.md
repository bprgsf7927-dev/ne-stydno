# Аккаунты v2 — вход по логину и паролю, ник, друзья

Дата: 2026-11-10. Статус: утверждено к работе (архитектура — Алена и Claude). Заменяет вход через Telegram из спеки `2026-11-08_akkaunty.md`. Синхронизация прогресса, мягкое предложение сохранить прогресс, кабинет и аватар из той спеки остаются в силе.

## Почему меняем

- Вход через Telegram зависел от связи Telegram ↔ Yandex Cloud, а с весны 2026 российские провайдеры режут Telegram Bot API. Вход ломался бы от внешних блокировок.
- Логин и пароль не зависят ни от мессенджеров, ни от чужих сервисов, не требуют персональных данных и денег (в отличие от SMS), работают на любом телефоне и компьютере.
- Вход через Telegram, VK ID и Яндекс ID — в бэклоге. Архитектура позволяет добавить их позже к тому же аккаунту без переделки.

## Секция 0. Решения

### Аккаунт и способы входа

- **Аккаунт** — внутренний случайный номер (`uid`). Его никто не видит.
- **Способы входа привязаны к аккаунту.** Сейчас один — логин и пароль. Позже к тому же `uid` добавятся Telegram, VK ID, Яндекс ID.
- **Логин** — только для входа, его никто не видит. Латиница, цифры, точка, подчеркивание; 4–20 символов; уникальный; без учета регистра. Подсказка при регистрации: «Не используй имя и фамилию».
- **Пароль** — от 6 символов, без требований к сложности, но не из списка самых частых («123456», «qwerty», совпадает с логином). Кнопка «показать пароль». Храним только хэш (`crypto.scrypt` с солью), сам пароль не храним и не логируем.
- **Код восстановления** — 12 символов группами (`K7QM-4TXA-9PRD`), показываем один раз при регистрации: «Сохрани или отправь маме». Храним только хэш. Забыл пароль → логин + код → новый пароль и новый код.
- **Защита от подбора:** после 5 неверных попыток — пауза 15 минут для этого логина, после 15 — на час.
- **Сессия** — подписанный токен на полгода (как сейчас). При смене пароля все сессии сбрасываются (номер версии в аккаунте).
- **Удаление аккаунта** — в кабинете, с подтверждением паролем. Стирает аккаунт, прогресс, вход, друзей.

### Ник

- **Ник собирается из генератора**, свой текст ввести нельзя (опыт LEGO). Два слова: прилагательное + существительное, согласованные по роду: «Хитрый Енот», «Бодрая Сова», «Задумчивый Пельмень».
- Крутим генератор, пока не понравится. Сменить можно в любой момент.
- Ники могут повторяться — друзья различают друг друга по аватару, а добавляют по коду друга.
- Списки слов придумывает Даня (это вовлечение и стиль), Алена и Claude проверяют: нейтральные, смешные, без обидных и двусмысленных сочетаний. Списки — в репозитории, в коде, отдельным файлом.
- Так решаются сразу три задачи: нет запрещенных ников, нет настоящих имен (а значит, нет персональных данных в профиле) и нет контактов в нике («добавь меня в тг @…»).

### Друзья (этап 2б, после входа и синхронизации)

- **Профиль не ищется.** Поиска по нику нет. Добавить можно только по коду друга.
- **Код друга** — 6 символов + QR + ссылка. Живет 48 часов, обновить можно в любой момент (старый перестает работать). Так код из общего чата класса не станет постоянной дверью для чужих.
- **Дружба по взаимному согласию:** заявка → «принять» / «отклонить». Отклонение молчаливое.
- **Что видят друзья:** ник, аватар, экспа за неделю, огонь, короны.
- **Общение только готовыми средствами:** реакции стикерами в стиле тренажера (рисует Даня), вызов на качалку или босса. **Свободного текста, личных сообщений, фото и голоса нет нигде.**
- **Лидерборд — только среди друзей.** Глобального рейтинга с незнакомцами нет.
- **Удалить из друзей** — молча. **Пожаловаться** — жалоба сохраняется, Алена разбирает.
- **Лимиты:** не больше 100 друзей, не больше 20 заявок в день.

### Данные

**Храним:** `uid`, дату создания, логин, хэши пароля и кода восстановления, счетчик неверных попыток, ник, аватар (набор частей), прогресс, список друзей и заявок, коды друга, жалобы.

**Не храним:** имя, фамилию, возраст, класс, школу, телефон, почту, фото, геолокацию.

- Данные — в России (Yandex Cloud, Object Storage), как сейчас.
- Логи функции без IP-адресов и тел запросов; срок хранения логов — 3 дня (настраивает Алена в консоли).
- Страница «Какие данные мы храним» (`privacy.html`) простыми словами для детей и родителей: что храним, что не храним, как удалить аккаунт, куда писать.
- **Триггер на юриста:** до того, как появятся Telegram, VK ID, Яндекс ID (настоящие идентификаторы людей), родительские функции или платные фичи. Это тот же момент, когда делим репозиторий на публичный и приватный.

### Хранилище (набросок, Claude уточнит в коде)

Object Storage, по JSON на объект:

- `acc/<uid>.json` — профиль: ник, аватар, дата создания, версия сессий.
- `prog/<uid>.json` — прогресс.
- `login/<логин>.json` — `uid`, хэши пароля и кода восстановления, неверные попытки, пауза до.
- `fcode/<код>.json` — `uid`, срок жизни.
- `friends/<uid>.json` — друзья и заявки.
- `reports/<дата>-<случайное>.json` — жалобы.

Открытый технический вопрос: уникальность логина при одновременной регистрации. Проверить условную запись (`If-None-Match`) в Object Storage; если не поддерживается — перейти на YDB Serverless (тоже Yandex Cloud, бесплатный уровень).

### API функции

- `POST ?r=register` — логин, пароль, ник, аватар → токен и код восстановления.
- `POST ?r=login` — логин, пароль → токен.
- `POST ?r=recover` — логин, код восстановления, новый пароль → токен и новый код.
- `POST ?r=password` — старый и новый пароль (с токеном).
- `GET/PUT ?r=progress` — как сейчас.
- `PUT ?r=profile` — ник, аватар.
- `DELETE ?r=account` — с паролем.
- Друзья (этап 2б): `POST ?r=fcode`, `POST ?r=friend-add`, `POST ?r=friend-answer`, `GET ?r=friends`, `POST ?r=react`, `POST ?r=report`.
- Счетчик `?r=ping` и `?r=stats` — без изменений.
- Маршруты Telegram (`?r=start`, `?r=tg`, `?r=check`, `?r=setup`) убираем из кода, сохраняем в истории git для бэклога.
